# Final submission checklist

Passing the automated tests is one part of the submission. Complete the report,
GitHub requirement records and the single group recording as well.

## Requirements and GitHub
- Agree at least 20 unique requirements across the whole group, drawing on the earlier assignments.
- Confirm priority separately from complexity, with a reason for each classification.
- Confirm at least eight high-complexity and eight medium-complexity requirements.
- Add the missing authentication and results requirement issues after the owners agree their wording.
- Assign every requirement issue to its actual owner in GitHub.
- Update old issue descriptions and checkboxes to match the integrated code and API.
- In particular, reconcile CAND-01 issue #12: its closed state and old implementation text disagree.
- Link each issue to its implementation commits or pull request, tests and report section.
- Record each requirement as fully implemented, partially implemented or not implemented after checking its acceptance criteria.
- Do not treat a reserved ID, closed issue or passing test count as proof that a whole requirement is complete.

## Report
Use simple language and plain tables without coloured shading.
- Add every member's name, student ID, GitHub ID and the repository link.
- Put the contribution table near the beginning, with requirement IDs, status and report section references.
- Explain how duplicate requirements were merged and how the final set was selected.
- For each requirement, compare potential solutions, costs, benefits and disadvantages; explain the selected solution.
- Describe the stack and architecture, including browser, APIs, databases and trust boundaries.
- Include selected code snippets with file names and explain the security behaviour they provide.
- Add evidence of successful operations and rejected requests, with captions explaining the outcome.
- Include the final main-branch test result, merged integration pull request and dated contribution history.
- Explain limitations, including MFA enrolment, ballot identity separation and audit history truncation.
- Check that every figure and requirement has a report reference and that no passwords or tokens appear in screenshots.

## Recording and handover
- Make one 17–20 minute recording with all members participating.
- Each member turns on their camera and says their name at the start of their part.
- Cover requirements and solution selection, architecture, a working demo and code for at least ten important security requirements.
- Allocate time within the overall limit; the suggested section times in the brief add up to more than 20 minutes.
- Use a fresh isolated demo database for a repeatable lifecycle demonstration; preserve existing completed election data.
- Check the recording opens, is audible and shows readable text.
- Submit the report, recording and repository link, with access available to the marker.
- Ensure the final submitted revision is on main and the relevant CI run has passed.
